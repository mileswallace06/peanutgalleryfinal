# Purchase transfer-platform follow-up

Reviewed base: `3a56073ba06f9f25b42844d2ca67068dafd4c554`.

The purchase page already requests its listing through `getListingParticipantView`. That endpoint omitted `transfer_platform`, so the actual `TransferAssistant` could not show the known Ticketmaster/AXS shortcut. The repair adds the Listing schema's six-value enum inside the existing seller / confirmed-buyer / admin serializer branch. No authorization decision or private-field allowlist is widened. Public listings omit the new field. Unknown/malformed/missing values become null. The separate seller `list_mine` projection retains its exact 26 keys.

## Evidence

- `red-green-summary.json`: actual endpoint tests failed 16/21 on the reviewed base, then passed 21/21 after the repair. The five pre-existing privacy-contract checks were already green before the repair.
- `before-browser.json`: actual `PurchaseSuccess`/`TransferAssistant` failed the known Ticketmaster shortcut assertion while consuming the old endpoint response. The generic guidance is visible in `before-ticketmaster-light.png`.
- `after-browser.json`: 14 checks pass across light/dark themes, covering Ticketmaster and AXS exact links, generic fallback for an unknown platform, and buyer/admin/guest/intruder presentation. There were zero JavaScript errors, blocked SDK calls or network attempts. The new shortcuts are visible in `after-ticketmaster-light.png` and `after-axs-light.png`.

The browser fixture imports responses generated by executing the actual backend handler in Node, with only SDK/auth/storage boundaries replaced by synthetic data. It does not hand-add `transfer_platform`. Unit tests also pass that endpoint response through the production `readAuthorizedPurchase` and `readPurchaseContext` functions. They check exact public and seller-list key sets, role authority, missing-sidecar behavior and private-field canaries. No raw Listing fallback is added.

## Limits

These are isolated synthetic endpoint and component tests, not hosted Base44 authorization or real ticket-provider tests. No provider link was followed, no transfer or payment was triggered, and no endpoint was deployed. Pending transfers still use the already-documented legacy Purchase context after participant authorization; this repair does not change that dependency. Refund, payout, tracking and Account Transfer policy remain untouched.
